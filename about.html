We will be building the MacPack website for the client.

2. Purpose

The MacPack website is a hub for members to view live updates of tournament brackets, see rankings, and showcase the club.

3. Data Description

Teams table:
Stores all teams that can participate in a tournament and contains basic information for each team.

  • id - key
  • name - text

Tournaments table:
This table stores each tournament, its scheduled date and status.

  • id - key
  • scheduled_at - date
  • status - text, “completed”, “scheduled”, “ongoing”

Tournament teams table:
This table links teams to the tournaments they are participating in.

  • tournament_id - key
  • team_id - int

Matches table:
This table represents each match within a tournament bracket.

  • id - key
  • tournament_id - int
  • round - int
  • match_number - int
  • status - text, “completed”, “scheduled”, “ongoing”
  • next_match_id - int

Match participants table:
This table stores the two teams competing in each match and the outcome.

  • match_id - key
  • slot - key (1 or 2, left team or right team)
  • team_id - integer
  • source_match_id - integer
  • score - integer
  • is_winner - boolean

4. Functions performed by the app

Homepage with navigation bar

  • Database effect: SELECT (retrieve basic tournament information if displayed)
  • Client-side: Just static ui with navigation links
Calendar page that shows game times
  • Database effect: SELECT (from matches table where status = "scheduled")
  • Client-side: Match calendar that shows up coming games. This will be a grid.
Live bracket (PackBrack)
  • Database effect: SELECT (retrieve matches and match_participants), UPDATE (update match results, winners, and match status)
  • Client-side: The bracket should be adjustable for 8-10 teams. It will look like a tree structure.

8. Client Feedback

1. Inquiry: How many team members and how do you want the team to be shown?
Client: We want our core 8 execs to have personal images and discriptions and for our general reps a team picture displayed.

2. Inquiry: How many teams play for the tornaments and what bracket style do you want displayed?
Client: We have 8-10 teams, and we want the basic simple two sided bracket style, we should be able to change this on our side.

3. Inquiry: Do we want users to make accounts in order to make changes to the live game bracket?
Client: No, we just want a simple password we can share and change.

4. Inquiry: What type of animation is key for this website?
Client: We want our past participates and events to be displayed.

5. Inquiry: What are your expectations. explain the live bracket page.
Client: We want a simple page where users can either log in with a password or just spectate. When accessed, the user should be able to input team names, scores and game start and end time. The bracket should show winners, game times and a ;eaderboard.

6. Inquiry: What do we want to put into the calender page?
Client: We have tornaments we want to add and drop in days. Drop in days are just short2-3 hour events, where people can gather to play some drop in volleyball with club supporters. These times and dates should be in the calender.
